# DAREU LM113 跨平台驱动开发规划 (2026-10-05)

## 1. 调研与逆向验证结论

通过对原驱动二进制文件与当前插入设备的逆向分析与脚本验证，得出以下核心结论：
- **方案商与架构**：采用荣腾科技（Rongteng）定制的 Holtek（盛群）USB MCU 方案，设备为免驱标准 USB HID 复合设备（包含键盘、鼠标与 Vendor-Defined 配置接口）。
- **通信通道**：上位机通过标准 USB HID 与 `UsagePage: 0xff01` 的 Vendor 接口通信。
- **报文协议与密钥**：
  - 配置下发：采用 **9 字节 HID Feature Report**（1 字节 ReportID + 8 字节 Payload）。
  - 协议混淆：原驱动使用对称混淆算法（字节对调 + 循环位移 + XOR + 密钥掩码），硬编码密钥字符串为 **`RoNgtEng`**（`52 6f 4e 67 74 45 6e 67`）。
  - 状态上报：鼠标通过 Interrupt In 上报 4 字节数据（如 `0x06, 0x07, ..., stage`）通知 DPI 档位切换。
- **跨平台可行性**：Windows / Linux / macOS 采用纯托管 `HidSharp` 栈通信（零 Native C DLL 依赖）；Linux 仅需一条 `udev` 规则开放设备读写。

## 2. 技术选型与参考基线

- **核心框架**：.NET 10 / C# 13 + Avalonia 11 (Fluent 现代毛玻璃 UI)。
- **硬件通信**：纯 C# 跨平台 HID 栈（Win: `hid.dll`, Linux: `/dev/hidraw`, Mac: `IOKit`）。
- **参考工程**：以 `KugouMusic.NET` 与 `dart-flutter-demo` 为基线，复用现代 MVVM 架构与精细化 CI 关键词触发流水线。

## 3. 分阶段开发规划 (5 大阶段)

### 阶段一：协议编解码器与通信 PoC 验证
- **目标**：在 Python 虚拟环境中完成完整指令闭环，并移植到 C# 协议基础库。
- **工作项**：
  1. 实现 `RoNgtEng` 混淆算法与逆向解密算法的 C#/Python 对应版本。
  2. 构造 DPI 切换（200~6400）、回报率（125/250/500/1000Hz）、灯效模式（常亮/呼吸/霓虹/RGB颜色）的 Feature Report 数据包。
  3. 执行实机写入测试，验证鼠标灯光与灵敏度实时生效；监听读取 4 字节 DPI 上报包。
- **交付物**：`Dareu.LM113.Protocol.Tests` 单元测试与端到端控制台 PoC。

### 阶段二：核心领域模型与驱动服务层封装
- **目标**：封装设备抽象层，屏蔽底层 USB HID 细节，提供强类型领域接口。
- **工作项**：
  1. 建立数据模型：`MouseProfile`、`DpiStageConfig`、`LightingConfig`、`KeyBindingConfig`。
  2. 实现 `DareuDevice`：负责设备热插拔自动检测、连接维持与重连机制。
  3. 实现板载配置拉取与落盘序列化（兼容原版 `p1.bin` / JSON 格式配置导出导入）。
- **交付物**：独立的 .NET 类库 `Dareu.LM113.Core` 与 `Dareu.LM113.Protocol`。

### 阶段三：Avalonia 现代桌面 GUI 开发
- **目标**：构建跨平台响应式桌面端界面，提供远超原版 Qt4 体验的现代交互。
- **工作项**：
  1. 引入原版鼠标高精度皮肤资源，制作交互式鼠标键位指示大图。
  2. **DPI 页面**：彩色档位滑块、多段开关、X/Y 轴独立灵敏度、回报率单选框。
  3. **灯光设置页**：灯效模式选择（常亮/呼吸/霓虹/关闭）、HSV/RGB 拾色器、R-B-G 物理引脚校正开关。
  4. **按键映射页**：按键重映射下拉列表、多媒体键支持、宏按键配置面板。
- **交付物**：Avalonia 主工程 `Dareu.LM113.App`。

### 阶段四：跨平台系统适配与 Linux 包集成
- **目标**：解决 Linux 与 macOS 平台的硬件访问权限与环境依赖，提供标准发行包。
- **工作项**：
  1. **Linux 权限与集成**：内置 `udev` 规则自动检测与安装向导（VID 0x260d / 0x258a 设备 0666 权限）；配置桌面菜单项 `dareu-lm113.desktop` 与应用图标。
  2. **Linux 多包格式**：同时提供通用绿色 `tar.gz` 与开箱即用的 Debian/Ubuntu `deb`、Fedora/RHEL `rpm` 安装包。
  3. **macOS 适配**：配置应用签名标识，处理 IOHID 权限提示与菜单栏适配。
- **交付物**：`linux/` 下 `udev` 规则、安装脚本、`.desktop` 文件及多格式打包流水线。

### 阶段五：GitHub Actions 关键词控制 CI/CD 与全自动 Release
- **目标**：参考 `dart-flutter-demo` 的触发设计，实现基于 Commit 关键词的精准构建与 GitHub Release 发布。
- **工作项**：
  1. **关键词触发机制**：
     - `[build-artifact]`：矩阵构建全平台产物并上传 7 天 Actions Artifact，不创建 Release。
     - `[build-release]`：超集模式，全平台构建产物 + 自动生成 Tag/Release Notes + 创建 GitHub Release 挂载资产。
     - 手动 `workflow_dispatch`（带 `publish: boolean` 选项）与 Git Tag `v*` 原生支持。
  2. **多平台构建矩阵**：
     - Windows: `win-x64`, `win-arm64`（单文件免安装 ZIP）。
     - Linux: `linux-x64`, `linux-arm64`（发布便携 `tar.gz`，并在 x64 平台打包 `deb` 与 `rpm`）。
     - macOS: `osx-x64`, `osx-arm64`（发布便携 `tar.gz`）。
- **交付物**：`.github/workflows/release.yml`、`scripts/ci/ci-trigger.py` 与自动化发布体系。

## 4. 关键里程碑与风险防范

1. **协议逆向准确率**：已通过 Capstone 反编译定位核心混淆算法 `0x403410` 与密钥 `RoNgtEng`，实机验证通过。
2. **多硬件固件与通道差异**：已在底层协议层与 GUI 预留 R-B-G 物理引脚交换开关，灵活适配不同批次固件。
3. **CI 免费额度保护**：通过精细化 commit 关键词过滤，日常开发不无谓消耗 Actions 额度，需要时一键发布。
